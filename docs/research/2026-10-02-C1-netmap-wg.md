## 1. netmap payload 全景：MapResponse → NetworkMap

### 1.1 通道与形态

- MapRequest JSON 字段（`POST /machine/map`，archived ts-main/tailcfg.go:1436-1548）：`Version`(CapabilityVersion)、`Compress`("zstd"|""；本仓恒发 "")、`KeepAlive`、`NodeKey`、`DiscoKey`、`Stream`、`Hostinfo`、`MapSessionHandle/MapSessionSeq`、`Endpoints`、`EndpointTypes`、`TKAHead`、`ReadOnly`(已废弃恒 false，行 1510-1511)、`OmitPeers`、`DebugFlags`。本仓 `encodeMapRequest`（packages/control/src/tailcfg.ts:155-169）与该结构对齐（未发 `EndpointTypes`，v1.102.3 仍兼容）。
- MapResponse（archived ts-main/tailcfg.go:2006-2215）：**全字段"零值=不变"**（行 1996-2005 的总注）。关键字段行号：`Node` 2042、`DERPMap` 2046、`Peers` 2055、`PeersChanged` 2060、`PeersRemoved` 2062、`PeersChangedPatch` 2071、`PeerSeenChange` 2076、`OnlineChange` 2079、`DNSConfig` 2083、`PacketFilter` 2112、`PacketFilters` 2136、`Health` 2154、`ControlTime` 2177、`Debug` 2195。
- 全量 vs 增量的裁决规则（v1.102.3 control/controlclient/map.go:790-812 `updatePeersStateFromResponse`）：
  - `Peers` 非空 ⇒ **全量替换**（keep-set 之外全删），且 **`Peers` 出现时忽略一切其他 delta**（map.go:810-811 注释 "Peers precludes all other delta operations"）；
  - 否则依次应用 `PeersRemoved` → `PeersChanged`（整 Node 覆盖）→ `PeerSeenChange`（只改 LastSeen）→ `OnlineChange`（只改 Online）→ `PeersChangedPatch`（字段级 patch）。
- `PeersChangedPatch`（`tailcfg.PeerChange`，v1.102.3 tailcfg.go:3348-3387）字段级语义：`DERPRegion`(≠0 ⇒ HomeDERP=该值)、`Cap`(≠0)、`Endpoints`(非 nil 整体替换)、`Key`/`DiscoKey`(指针非 nil 才替换)、`Online`/`LastSeen`/`KeyExpiry`(指针语义)、`KeySignature`、`CapMap`(非 nil 整体替换)。patch 应用代码 map.go:853-901；**未知 NodeID 的 patch 直接忽略**（map.go:854-857）。oracle metrics 里 `controlclient_patch_endpoints/patch_key/patch_online/patch_derp/patch_discokey` 计数器（protocol-notes.md:222-224）与 map.go:862-898 的 `patchXxx.Add(1)` 一一对应，实证该机制在真实 headscale 环境**在用**。
- MapResponse → `netmap.NetworkMap` 的落点：全量路径走 `ms.netmap()`（map.go:1239）后 `netmapUpdater.UpdateFullNetmap(nm)`（map.go:365）；`NetworkMap` 结构体字段见 v1.102.3 types/netmap/netmap.go:29-80（`SelfNode`/`Peers`(按 ID 排序，行 38)/`DNS`/`PacketFilter`/`DERPMap`/`Domain`…）。本仓 oracle 转储（`tailscale debug netmap`）就是它的 JSON 视图（protocol-notes.md:162-180）。

### 1.2 收到 Node 后的归一化（upgradeNode）——必须在解码层做

v1.102.3 control/controlclient/map.go:384-416 `upgradeNode`，对 `Node`/`Peers[]`/`PeersChanged[]` 每项执行（map.go:294/311/314）：

1. **legacy DERP 字段**：JSON 键名是 **`"DERP"`** 不是 "LegacyDERPString"（archived ts-main/tailcfg.go:416 `json:"DERP,omitzero"`）；值形如 `"127.3.3.40:N"`（`DerpMagicIP = "127.3.3.40"` 常量在 v1.102.3 tailcfg.go:3394；archived tailcfg.go:406-416 注释同义）。upgradeNode：`HomeDERP==0` 时解析 `DERP` 字段，`ip=="127.3.3.40"` 则 `HomeDERP=N`，随后清掉 legacy 字段（map.go:390-401）。**实现陷阱：headscale 老版本可能仍发 `"DERP":"127.3.3.40:17"`，必须兼容。**
2. **AllowedIPs null = Addresses**（capver 112 起，archived ts-main/tailcfg.go:163 + 397-402 注释）：`if n.AllowedIPs == nil { n.AllowedIPs = slices.Clone(n.Addresses) }`（map.go:406-407）。**注意 nil 与 [] 语义不同**：JSON `null` ⇒ 视同 Addresses；`[]` ⇒ 空（无前缀，见 §2.4）。
3. **UnsignedPeerAPIOnly 钳制**：此类节点 AllowedIPs 强制等于 Addresses（map.go:411-414），且其流量必须过 PacketFilter 校验（archived ts-main/tailcfg.go:488-493）。

### 1.3 过期（Expired）的客户端防御——直接决定"这个 peer 是否存在"

- 客户端时间基准：`MapResponse.ControlTime` 与本地时钟差 > 1min 时记录 `clockDelta`（v1.102.3 ipn/ipnlocal/expiry.go:28, 65-74）。
- 每帧 netmap 到达即 `flagExpiredPeers`（ipn/ipnlocal/local.go:1838-1840）：对 `KeyExpiry` 非零且 ≤ (本地时间+clockDelta) 的 peer：`Expired=true`、**清 `Endpoints`、清 `HomeDERP=0`**、并把公钥字节前 6 字节替换为 `badOldPrefix = [109,167,116,213,215,116]`（expiry.go:116-135；字节表在归档 key-node.go:229）。也就是说：**过期 peer 在推导输入端就已经是"无端点、无 DERP、键被破坏"的状态**，路由层（§2）再按 `Expired()` 二次剔除。
- 过期判定必须用注入时钟（本仓 P4：`common` 的 `Clock.wallMs()`），`KeyExpiry` 是 RFC3339 时间字符串。

## 2. allowed_ips 推导（核心语义）

### 2.1 现行架构：WG 设备按公钥懒建 peer

v1.102.3 关键链条：

- `wgcfg.NewDevice` 创建 wireguard-go 设备；`NewPeerLookupFunc(bind, logf, allowedIPsFn)` 返回的 lookup 被装入设备：**用 32B 公钥查 allowed_ips；查得到就建 peer，`Endpoint` 也是从公钥派生**（wgengine/wgcfg/device.go:24-40，其中 `bind.ParseEndpoint(fmt.Sprintf("%x", pubk[:]))`，device.go:30）。
- 引擎侧安装该回调：`e.wgdev.SetPeerLookupFunc(wgcfg.NewPeerLookupFunc(e.wgdev.Bind(), …, fn))`，`fn = LocalBackend.peerAllowedIPs`（wgengine/userspace.go:685-697；安装点 ipn/ipnlocal/local.go:615）。单个 peer 的 allowed_ips 变化用 `SyncDevicePeer(k)` 推送：查不到前缀 ⇒ `RemovePeer`（userspace.go:699-718）。
- 出站包的 peer 选择：`SetPeerByIPPacketFunc` → `LocalBackend.lookupPeerByIP`（ipn/ipnlocal/resolve.go:19-41）：先精确匹配 node 地址表（`NodeByAddr`），再查 RouteManager 出站表（子网路由/exit）。

### 2.2 netmap Node → RouteManager（peerViewOf：前缀从哪来）

v1.102.3 net/routemanager/routemanager.go:408-432 `peerViewOf(n tailcfg.NodeView)`：

- **AllowedIPs 是唯一前缀来源**（routemanager.go:387-392 注释 + 404 注释 "AllowedIPs is the sole source of prefixes; an address absent from AllowedIPs is not routable"）。`Addresses` 只参与"哪些 AllowedIPs 算 self 地址"的判定，绝不直接变成前缀。
- 两个"不可通信"剪枝（剪完仍按 ID/Key 跟踪，便于后续复活，routemanager.go:397-402）：
  - `n.Expired()` ⇒ 不贡献任何前缀（routemanager.go:416-418）；
  - `DiscoKey.IsZero() && HomeDERP==0 && !IsWireGuardOnly` ⇒ 不贡献前缀（routemanager.go:419-421；注释 "predating both DERP and disco"）。经典实现同款剪枝：v1.48.2 nmcfg.go:88-92（`peer.DiscoKey.IsZero() && peer.DERP == "" && !peer.IsWireGuardOnly`）。
- AllowedIPs 逐条分类（routemanager.go:422-430）：
  - `isSelf := (单 IP && tsaddr.IsTailscaleIP(addr)) || 前缀 ∈ n.Addresses` ⇒ `SelfAddrs`；
  - 其余 ⇒ `Routes`（子网路由 + exit node 的 0.0.0.0/0、::/0）。
  - `IsTailscaleIP` = `100.64.0.0/10`（刨去 ChromeOS `100.115.92.0/23`）∪ `fd7a:115c:a1e0::/48`（net/tsaddr/tsaddr.go:70-98；CGNAT 定义 tsaddr.go:31-35）。
- 同时从 Node 摘出的数据面属性：`Jailed=IsJailed`、`MasqAddr4/6=SelfNodeV{4,6}MasqAddrForThisPeer`（routemanager.go:409-414；字段语义 archived ts-main/tailcfg.go:514-542）。

### 2.3 哪些前缀最终进 WG allowed_ips（eligible）

`PeerAllowedIPs(id)`（routemanager.go:274-297）= 该 peer 全部贡献前缀中过 `eligible` 的，**排序后返回**（tsaddr.SortPrefixes，routemanager.go:295）；**返回空 ⇒ 这个 peer 不应存在于 WG 设备**（routemanager.go:265-266 注释）。`eligible`（routemanager.go:827-840）：

| 前缀类别 | 进 WG allowed_ips 的条件 |
|---|---|
| `kindSelf`（peer 自身地址） | 恒进，除非 tailnet 配置 `DisableIPv4` 且是 IPv4（routemanager.go:828-832） |
| `kindRoute` 且是 **exit 路由**（`0.0.0.0/0` 或 `::/0`，`tsaddr.IsExitRoute` tsaddr.go:270-273） | 仅当**该 peer 正是被选中的 exit node**（`prefs.ExitNodeID` 匹配，routemanager.go:833-836） |
| `kindRoute` 其他（子网路由） | 仅当 `prefs.RouteAll==true`（routemanager.go:837） |
| `kindExtra`（conn25 Transit IPs 等扩展注入） | 恒进 WG allowed_ips，但**永不进 OS 路由**（routemanager.go:159-163, 839） |

- prefs 映射（routemanager.go:106-128）：`ExitNodeID`（0=未选）、`ExitNodeSelected`、`RouteAll`。oracle 环境 `RouteAll:true`、未选 exit node（protocol-notes.md:211）⇒ 我们的默认推导应装入 self 地址+子网路由、剔除两条 /0。
- 经典实现交叉验证（v1.48.2 wgengine/wgcfg/nmcfg/nmcfg.go:54-133 `WGCfg`）：`/0` 且非选中 exit node ⇒ 剔除（行 103-115）；子网（非单 IP、或单 IP 不在 Addresses，`cidrIsSubnet` 行 38-52）且无 `AllowSubnetRoutes` flag ⇒ 剔除（行 122-129）；其余原样装入 `peer.AllowedIPs`（行 130）。**两代语义一致，规则收敛可信。**
- 前缀归一化防御：**host bits 置位的非法前缀直接跳过并记日志**（routemanager.go:655-687 `normalizePrefix`/`contribs`）。TS 实现解析 `"ip/bits"` 时必须 `mask()` 后比较。
- OS 路由聚合（OneCGNAT /10 vs 每 peer /32、cgnatThreshold=10000，routemanager.go:137-148, 213-215）只影响 **OS 路由表**，不影响 WG allowed_ips——鸿蒙端若暂不做 OS 路由注入，可整体忽略（见 §5 knob `one-cgnat`）。

### 2.4 自机（self）推导

- `wgcfg.Config{PrivateKey, Addresses: nm.GetAddresses()}`（ipn/ipnlocal/local.go:6100-6110；私钥与 netmap NodeKey 不符则清零）。**自机只取 `SelfNode.Addresses` 作接口地址；SelfNode.AllowedIPs 不进 WG 配置。**
- `NetworkMap.GetAddresses()` = `SelfNode.Addresses()`（types/netmap/netmap.go:91-99）。

## 3. key 语义（WG 层公钥的来源与形态）

- 文本格式（归档 docs/upstream/ts-main/key-node.go）：`nodekey:` + 64 小写 hex（前缀常量行 36；Marshal/Unmarshal 行 333-347）；私钥 `privkey:`（行 29，注释说明这是历史包袱）；disco 公钥 `discokey:`（docs/upstream/2026-10-01-phase2/key-disco.go:23）。JSON 里 `Node.Key`/`Node.Machine`/`Node.DiscoKey` 无 json 改名（archived tailcfg.go:388, 391-392），即 wire 值就是 `"nodekey:<hex64>"` 等形态（oracle 实测同，protocol-notes.md:167-168）。
- 二进制形态 = 32B 原始字节（`NodePublicRawLen=32`，key-node.go:44；`Raw32()` 行 299）。WG 设备层用 `pubk.Raw32()` 做 peer 键（userspace.go:694-695, 712, 715）。**本仓衔接：`hexDecode(key.slice("nodekey:".length))` → 32B → `WgPeerTable.registerPeer`（packages/wireguard/src/peers.ts:45-56 已校验 32B）。**
- **Key 轮换**：peer 的 nodekey 变化走 `PeersChangedPatch.Key`（§1.1）；magicsock 侧同 NodeID 新 Key ⇒ 删除旧 endpoint 重建（magicsock.go:3205-3210），并按新 Key 清理 derpRoute/peerLastDerp（magicsock.go:3151-3158）。**WG 层等价操作 = 用旧 peerId（旧 key hex）`removePeer` + 新 key 重新 register**——peers.ts:89-100 的 removePeer 已能级联清会话。
- `Node.Cap`（archived tailcfg.go:427）是**对端节点的 CapabilityVersion**（非能力集合），oracle tailnet 全部 142（protocol-notes.md:169）= 上游 v1.102.3 的 `CurrentCapabilityVersion=142`（v1.102.3 tailcfg.go:192）。仅 magicsock 用它判 peer-relay 能力（`capVerIsRelayCapable(n.Cap())`，endpoint.go:1554），一期可记录不解码。
- 尾注：`Machine`/`ControlPrivate` 的 JSON 序列化差异只涉及**本机** machine key（control.go:68-79，字节数组形态，Deprecated），peer 推导不涉及。

## 4. endpoint 语义（netmap 的 Endpoints/HomeDERP 如何变成"发往哪里"）

**结论：WG 协议层的 peer endpoint 不是任何 `ip:port`，而是 peer 公钥本身。** 真正的 UDP 目的地址由 magicsock（我们的 disco/DERP 层）在 netmap 候选里动态决策：

- wireguard-go 建 peer 时 `Endpoint = bind.ParseEndpoint(hex(publicKey))`（wgcfg/device.go:30）；magicsock 的 `ParseEndpoint(nodeKeyStr)` 把 64 hex 还原为公钥，返回它为该 peer 维护的 `endpoint` 对象，**不认识就报错**（"should never be telling WireGuard about a new peer before magicsock knows about it"，magicsock.go:3887-3910）。
- magicsock `endpoint` 的 netmap 喂入口（每帧/每 patch）：
  - `updateFromNode`（endpoint.go:1500-1555）：`DiscoKey` 变化⇒重置 disco；`HomeDERP` 变化⇒ `derpAddr = netip.AddrPortFrom(127.3.3.40, uint16(HomeDERP))`（endpoint.go:1540）——**DERP home 被编码成"假 UDP 地址"，IP 恒 127.3.3.40、端口=region ID**；`setEndpointsLocked(n.Endpoints())` 全量重建候选表（endpoint.go:1552, 1557-1600：新候选保留 index，消失的候选按老化策略删除）。`Expired` 记进 endpoint（endpoint.go:1513）。
  - 增量路径 `UpdateNetmapDelta` 只处理两类 mutation：`NodeMutationDERPHome`（`setDERPHome`）与 `NodeMutationEndpoints`（magicsock.go:3933-3951）——即 **patch 面里只有 HomeDERP/Endpoints 影响 endpoint 选择**，与 PeerChange 字段表吻合。
  - magicsock 拒收"零 DiscoKey 且非 WireGuardOnly"的 peer（magicsock.go:3217-3227, 3261-3265），与 §2.2 的路由层剪枝双保险。
- 发包决策 `addrForSendLocked`（endpoint.go:583-600）：`bestAddr` 受信 ⇒ 直连 UDP；否则 WireGuardOnly peer ⇒ 从 `Endpoints` 候选中按**已知延迟最低者**发送（无延迟数据时**随机选一个**只信 1s，endpoint.go:610-657，随机在 app 侧用注入 Rng 实现）；普通 peer ⇒ **bestAddr（过期也发）+ DERP 同时发**（endpoint.go:597-599）。
- 对端离线案例（oracle harmony-vm）：Endpoints/HomeDERP/DiscoKey 在 netmap 中**保留**（protocol-notes.md:114-124），我们应保持同样语义：不因离线删 peer，打洞失败退回 DERP 排队。

## 5. capability 与 knob 语义

### 5.1 能力载体

- `Node.Capabilities []string` 已弃用（archived tailcfg.go:457-464，Deprecated 指向 issue #11508）；现行 `Node.CapMap NodeCapMap`（archived tailcfg.go:466-486），类型 `map[cap][]json.RawMessage`（archived tailcfg.go:1626-1670：**值是 JSON 原文数组；"无值能力"= key 存在但值为空数组/nil，用 `Contains` 判**）。peer 侧同构为 `PeerCapMap`（archived tailcfg.go:1672-1712），来源是 FilterRule.CapGrant（archived tailcfg.go:1580-1596）。
- 旧服务器只发 `Capabilities` ⇒ 客户端把它**合并进 CapMap**（key 存在、value=nil）再统一处理（map.go:299-306）。capver 67 才有 PeerCapMap、74 才有 NodeCapMap（archived tailcfg.go:118, 125）。
- 三条下发路径（archived tailcfg.go:477-486）：① `MapResponse.Node.CapMap`（影响本节点行为）；② `PacketFilter(s)`（访问控制）；③ `MapResponse.Peers[].CapMap`（对端能力/偏好）。**knob 只从 ① 派生。**

### 5.2 knob = self CapMap 的投影（ControlKnobs）

- 类型：`control/controlknobs/controlknobs.go:20-143` `Knobs`（全部 atomic 字段）。更新入口 `UpdateFromNodeAttributes(capMap)`（controlknobs.go:145-213），**唯一调用点是收到带 `Node` 的 MapResponse 时**（map.go:307 `ms.controlKnobs.UpdateFromNodeAttributes(resp.Node.CapMap)`）。
- **属性串是"短名"，不是完整 URL**（v1.102.3 tailcfg.go:2478-2480 注释允许 URL 或 well-known 短名；实测常量表 tailcfg.go:2574-2828）。与数据面/发现面直接相关的条目（全部 v1.102.3 tailcfg.go 行号）：

### 5.3 能力与 allowed_ips 的间接耦合（不要混淆）

- CapMap/knob **从不直接改写** allowed_ips；耦合只有三条：
  1. self `UnsignedPeerAPIOnly`（Node 字段，非 cap）⇒ 自己的 AllowedIPs 被钳到 Addresses（map.go:411-414）；
  2. peer `IsJailed` ⇒ 数据面按更严过滤（routemanager.go:49-53），allowed_ips 不变；
  3. PacketFilter（含 `cap:<capability>` 源匹配，archived tailcfg.go:1727）决定"哪些入站包被放行"——是 WG allowed_ips 之外的**第二道独立门**（本仓 PacketFilter 过滤器属二期另一件，不在本笔记展开）。

## 7. 实现陷阱清单（按危害排序）

1. **`AllowedIPs: null` ≠ `[]`**：null ⇒ clone(Addresses)（map.go:406-407）；`[]` ⇒ 无前缀 ⇒ peer 从 WG 设备移除。JSON 解码必须区分 `undefined/缺失`、`null`、`[]` 三态（缺失按"不变"处理，仅增量帧；全量帧里缺失等同 null？——**上游 Go 解码后无区分，均走 nil 分支**，但全量帧 `Peers[]` 每项都应带字段；稳妥做法：全量帧缺失按 null 处理并在测试里钉死）。
2. **AllowedIPs 是唯一前缀来源**：禁止从 `Addresses`、`PrimaryRoutes` 拼路由；`PrimaryRoutes` 只是"当前主路由"展示口径（archived tailcfg.go:438-442）。
3. **两个剪枝先行**（§2.2）：`Expired` 或（无 DiscoKey && HomeDERP==0 && !IsWireGuardOnly）的 peer 不产生任何 allowed_ips；但**不要把它们从 netmap 状态里删掉**（要支持复活与离线保留，protocol-notes.md:114-124）。
4. **exit 路由 = 精确两条**：`0.0.0.0/0`、`::/0`（tsaddr.go:270-273）；只装"被选中的 exit node"的；未选中/其他 peer 一律剔除。`0.0.0.0/1` 这类"半个默认路由"不是 exit 路由，按子网路由走 RouteAll。
5. **isSelf 判定的两个 OR 分支**（routemanager.go:422-424）：单 IP 且属 CGNAT/ULA 两个 range（注意刨除 100.115.92.0/23 与 4to6/临时段——tsaddr.go:83-120）；或前缀原样 ∈ Addresses。子网路由中的单 IP（如 4to6 NAT 段）不算 self。
6. **前缀必须归一化**：`"100.100.0.4/33"`、`"fd7a::1/128"`（host bits 置位的网段）跳过并记日志（routemanager.go:665-687）；bits 越界在解析层就抛错。
7. **WG endpoint 是公钥 hex，不是 ip:port**：任何把 `Node.Endpoints` 直接塞进 WG 握手/传输层的实现都是错的（wgcfg/device.go:30；magicsock.go:3890-3910）。`Endpoints`/`HomeDERP` 只进发现层（disco/DERP）。
8. **HomeDERP 的假地址编码**：`127.3.3.40:regionID`（endpoint.go:1540；tailcfg DerpMagicIP 常量）；region ID 可能 >32767 吗——不会（DERPRegionID 实际 0-65535，本仓 TLV 用 u16be 足够，messages.ts:39）。
9. **Key 轮换的三处联动**：patch.Key 替换 netmap 状态 + magicsock 重建 endpoint + WG 层换 peerId；漏任何一处会出现"半旧会话"。旧 Key 的 32B 不得复用（KeyExpiry 到期同理，配合 §1.3 的 badOldPrefix 防御）。
10. **过期需要注入时钟**：`KeyExpiry`（RFC3339）与本地时间比较必须走 common `Clock`（P4）；`ControlTime` 时差校正可选，但**至少要在"恰好过期"边界留 10s 迟滞**（上游 timer 就是 `nextExpiry.Sub(now)+10s`，local.go:1856-1858）。
11. **增量裁决顺序**（§1.1）：`Peers` 非空 ⇒ 忽略其余 delta；`PeersChangedPatch` 只对已知 NodeID 生效；patch 字段均为"非零/非 nil 才生效"（map.go:853-901）。`disable-delta-updates` knob 出现时整帧按全量重建。
12. **knob 短名 ≠ URL**：knob 匹配用精确短名（§5.2 表）；`Capabilities`（旧字段）要并集进 CapMap 再判（map.go:302-306）。peer 的 CapMap 永远不参与 knob。
13. **IsWireGuardOnly peer 的特殊性**：无 disco/DERP 也能通（靠 Endpoints 直连，endpoint.go:590-595）；`PersistentKeepalive` 在两代上游 WG 配置里都**未设置**（nmcfg.go 与现行 config 均无）——不要自作主张加 25s keepalive。
14. **MasqAddr 字段**：`SelfNodeV4MasqAddrForThisPeer` 是"对端眼中的我"（archived tailcfg.go:514-527），属 SNAT 数据面属性；一期可先透传记录，勿误当作 allowed_ips 或 endpoint。
15. **JSON 数值域**：`NodeID` 可能超过 2^53（archived tailcfg.go:202-209）；TS 解码 JSON number 有精度风险——`StableID`（字符串）可作替代主键；若用 NodeID 建索引须防精度（Headscale 实测是小整数，oracle User map "1"，protocol-notes.md:77）。
