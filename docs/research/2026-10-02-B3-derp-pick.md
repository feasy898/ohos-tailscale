## 1. 结论总览（先答任务问题）

**上游在 region 内不做随机选节点。** 三层策略自上而下是：

1. **region 级（home 选哪个 region）**：netcheck 按「历史窗口内最低延迟（可被控制面 RegionScore 缩放）+ 换移迟滞」算出 `Report.PreferredDERP`（netcheck.go:1424-1531）；magicsock `maybeSetNearestDERP` 采纳之；**report 无数据（如 UDP 被封）时才随机兜底选一个 region**（ms-derp.go:108-148，`rands.IntN` PCG 伪随机，cheap.go:28-34）——这是上游整条链路里**唯一**的随机选择点，且发生在 region 级、不在节点级。
2. **节点级（region 内连哪个节点）**：DERP map 中 `DERPRegion.Nodes` 本身就是**控制面为当前客户端排好的优先序**（derpmap.go:171-183 原文："in priority order for the current client"）；客户端 `derphttp` 的 `dialRegion` **严格按数组序逐个尝试、首个可连即用**，跳过 `STUNOnly` 节点，全失败返回**第一个**错误（derphttp_client.go:636-657）。
3. **拨号级（单节点内怎么连）**：每个节点 IPv4/IPv6 竞速（显式 IP 优先于 HostName DNS），单节点拨号 1500ms 超时，IPv6 被认为可用时 IPv4 晚 200ms 发车，端口 443（DERPPort 可覆盖）（derphttp_client.go:729, 737-837）；整场连接（DNS+TCP+TLS+HTTP 升级+DERP 升级）共 10s 预算（derphttp_client.go:355-359）。

连到非 `Nodes[0]` 的节点时，客户端在 HTTP 升级请求里带上 `Ideal-Node: <Nodes[0].Name>` 头（纯统计用途；主动迁移回理想节点是 TODO 未实现，tracking issue #12724）（derphttp_client.go:439, 513-524；derp.go:160-164）。

**对本仓任务标题的勘误**：TASK.md:32 与【取证】§3（protocol-notes.md:138）的「同 region 多节点，客户端应随机挑选/故障切换」中，「随机挑选」**不是上游客户端行为**——上游是「按序回退」；「故障切换」成立（见 §5）。B-3 实现应按上游语义落为「按序回退 + region 级随机兜底」，理由即本节证据（TASK.md:36 B-1 上游对齐优先于编码）。

## 2. 数据结构语义（tailcfg/derpmap.go 实拉）

### 2.1 DERPRegion.Nodes = 控制面定制的优先序（derpmap.go:171-183）

```go
// Nodes are the DERP nodes running in this region, in
// priority order for the current client. Client TLS
// connections should ideally only go to the first entry
// (falling back to the second if necessary). STUN packets
// should go to the first 1 or 2.
//
// If nodes within a region route packets amongst themselves,
// but not to other regions. That said, each user/domain
// should get a the same preferred node order, so if all nodes
// for a user/network pick the first one (as they should, when
// things are healthy), the inter-cluster routing is minimal
// to zero.
Nodes []*DERPNode
```

四条可执行语义：
- 顺序即优先级，且**按当前客户端定制**（"for the current client"，derpmap.go:171-172）——随机性（若有）在上游控制面生成 map 时就已注入，客户端拿到什么序就用什么序；
- TLS（DERP 连接）只应打第 1 个，必要时第 2 个（derpmap.go:173-175）——注意上游自己的注释都只承诺回退到第 2 个，`dialRegion` 实现则是全列表回退（实现比注释更宽容，见 §4.2）；
- STUN 探测包打前 1–2 个（derpmap.go:175）——netcheck 实际用轮转实现，见 §3.2；
- 同 region 节点间可互转包（mesh），跨 region 不转（derpmap.go:177-179）——这解释了为什么客户端连到 region 内任何一个节点都能正常中继：**选哪个节点只影响负载与延迟，不影响正确性**。
- 服务端侧同款「不随机」佐证：client 短暂同时挂在同 region 多节点时，`multiForwarder` 固定向 preferred forwarder 转发，"don't pick randomly"（归档 derpserver.go:2996-3007）。

### 2.3 home 相关控制面参数（derpmap.go:15-66, 109-169）

- `DERPMap.HomeParams.RegionScore`（derpmap.go:49-66）：控制面对各 region 延迟乘的缩放系数；(0,1) 更偏好、(1,∞) 惩罚；缺失=1.0；**0 或负数被忽略**（netcheck.go:1447/1463 的 `score > 0` 判断）；nil map=不变、空 map=全部重置为 1.0。CapabilityVersion 65 起支持（归档 tailcfg.go:116）。
- `DERPRegion.Avoid`（derpmap.go:145-159）：**已废弃**——注释原文承认历史上实现有 bug、各处理解不一致，被 `NoMeasureNoHome` 取代；netcheck 中仅剩「Avoid region 若不是当前 preferred 则不探测」一处生效（netcheck.go:417-420）。
- `DERPRegion.NoMeasureNoHome`（derpmap.go:161-169）：**不测延迟、不选为 home；但 peer 的 home 在此则允许连**。CapabilityVersion 115 起支持（归档 tailcfg.go:166）。netcheck 在三处按此过滤：增量探测排序（netcheck.go:414-416）、初始探测（netcheck.go:563）、UDP 全挂后的 HTTPS 兜底列表（netcheck.go:1007）。
- `DERPRegionID`：900–999 为用户自建保留段（derpmap.go:76, 128-129）——与本仓 headscale embedded DERP 实测 region 999（【取证】protocol-notes.md:29）吻合。

## 3. region 级：home region 选择与随机兜底

### 3.1 netcheck 计算 PreferredDERP（netcheck.go:1424-1531）

`addReportHistoryAndSetPreferredDERP`（netcheck.go:1426）算法，按代码顺序：

1. **历史窗口**：报告入 `c.prev`，保留窗 `maxAge = fullReportInterval + ReportTimeout`（netcheck.go:1416，`fullReportInterval=5min`，netcheck.go:1379）；取窗口内**每 region 最低延迟** `bestRecent`（netcheck.go:1438, 1536-1546）。
2. **RegionScore 缩放**：`bestRecent[rid] *= score`（不回写原始报告）（netcheck.go:1442-1450）；本轮报告延迟在比较时同样缩放（netcheck.go:1458-1465）。
3. **取全局最小**：遍历本轮 `r.RegionLatency`，`best < bestAny` 者胜出 → `r.PreferredDERP`（netcheck.go:1470-1475）。
4. **换移迟滞（keepOld）**：若本轮选出的 ≠ 上次 `prevDERP` 且旧 region 仍可达（有本轮延迟，或 8s 内收到过该 region 的 DERP 帧/非 STUN 信号，`PreferredDERPFrameTime=8s`，netcheck.go:1392, 1486-1495），则满足任一就不换（netcheck.go:1480-1507）：
   - 绝对差 < `preferredDERPAbsoluteDiff = 10ms`（netcheck.go:1387）；
   - 新最优 > 旧 region 当前延迟 × 2/3（netcheck.go:1503-1506，"about the same on a percentage basis"）。
5. **强制覆盖**：`ForcePreferredDERP` 有延迟样本或 8s 内活跃 → 直接采用（netcheck.go:1513-1524）——对应【取证】§1.3 排除的 `tailscale debug force-prefer-derp` 调试命令（protocol-notes.md:54）。
6. **KeepAlive 兜底**：完全没有延迟数据、但旧 home 在 `2×derp.KeepAlive`（=120s）内有帧 → 维持旧 home（netcheck.go:1528-1530；`PreferredDERPKeepAliveTimeout` netcheck.go:1393-1401；`derp.KeepAlive=60s` derp.go:41-44）。

### 3.2 netcheck 的 STUN 探测：region 内节点是确定性轮转，不是随机

增量探测计划 `makeProbePlan`（netcheck.go:455-557）：

- 只探上次延迟最快的 `numIncrementalRegions = 3` 个 region，**且 home region 无条件强制在列**（#13969，防止 bufferbloat 下的一次离值把 home 抖走——netcheck.go:466-477 注释）；排序 `sortRegions`：按上次延迟升序、无数据垫底，`NoMeasureNoHome` 剔除、`Avoid` 非当前 preferred 剔除（netcheck.go:408-436, 441）。
- 每 region 的 STUN 发包次数 `tries`（netcheck.go:499-524）：

| 条件 | tries | 依据 |
|---|---|---|
| 默认 | 1 | netcheck.go:501 |
| 上轮最快的 2 个（`ri < 2`）或 home | 2 | netcheck.go:502-505 |
| **home 且已有旧 home** | 4（"try extra hard… don't flip flop around"） | netcheck.go:519-524 |

- **每次 try 的目标节点：`n := reg.Nodes[try % len(reg.Nodes)]`（netcheck.go:534；初始版同款 netcheck.go:570）——确定性轮转，无随机**。
- 重传间隔：`delay = try × (上次延迟×1.2)`，`try>1` 再加 `try×50ms`（netcheck.go:535-541）；初始计划（无历史）`try × defaultInitialRetransmitTime`（netcheck.go:569-571）。
- 初始全量计划：每 region 3 次尝试轮转前几个节点（netcheck.go:569-570）——即官方注释「STUN 打前 1–2 个」的落地形态。
- 探测收尾：`stunProbeTimeout` 到点或"saw enough regions"即停（netcheck.go:974-998）。

**UDP 全挂的降级链**（netcheck.go:1000-1058）：STUN 全无响应 → 对「无延迟数据 && 有 DERP 节点 && 非 Avoid/NoMeasureNoHome」的 region 起 HTTPS 测速：`measureHTTPSLatency` 经 `derphttp.DialRegionTLS`（**同样吃 §4.2 的按序回退**，其文档注释即"tried in sequence according to their order in the DERP map"，derphttp_client.go:680-685）建 TLS 后 `GET /derp/latency-check`（netcheck.go:1155-1227）；并行 ICMP 对 **`Nodes[0]`**、`STUNPort<0` 的节点跳过、以 `node.Name` 为 echo payload（netcheck.go:1275-1300）。js/wasm 的 HTTP-only 环境则 `HEAD /derp/probe` 打 `Nodes[0]`（netcheck.go:1112-1131）。

### 3.3 magicsock：采纳 report + 唯一随机兜底（ms-derp.go）

`maybeSetNearestDERP`（ms-derp.go:159-214）：

- **未连上控制面且已有 home → 不换 home**（换了 peer 也发现不了，ms-derp.go:160-195，引用 corp issue #18095）；但没有 home 时「有 DERP 总比没有强」，仍允许选（ms-derp.go:191-195）。

- 随机源 `rands.IntN(seed, n)`（cheap.go:28-34）：**栈上播种的 `math/rand/v2.PCG`（`Seed(seed, seed)`）+ Lemire 乘法归约拒绝采样**（cheap.go:42-90 附近 `uint64n`），无全局 RNG 状态、可复现——seed 取 Conn 指针地址，即「每实例一次定型、进程内确定性」。同包还有 `rands.Shuffle(seed, data)`（Fisher-Yates，cheap.go:17-21）。

- **随机的是 region 下标，不是节点**；且已被选中过的 `myDerp` 永远优先复用。

## 4. 节点级：region 内按序回退（derphttp_client.go 实读）

### 4.1 连接入口与预算

- `derphttp.Client` 持 `url` 或 `getRegion` 二选一（derphttp_client.go:81-83）；region 模式经 `NewRegionClient(privateKey, logf, netMon, getRegion)`（derphttp_client.go:121-139）。magicsock 为**每个 region** 建一个 region client，`getRegion` 回调在**每次拨号时**重读当前 `derpMapAtomic.Regions[regionID]`（ms-derp.go:399-415）——DERPMap 更新对已建连不动、对下次重连生效。
- `Connect` 幂等：已连直接复用；对外语义「Send/Recv 报错但不自动重试，**下一次**调用自动整体重建连接」（derphttp_client.go:52-56, 190-195）。
- 整场连接预算 10s：`const timeout = 10 * time.Second`，注释列举覆盖 DNS+TCP+TLS+HTTP Upgrade+DERP upgrade（derphttp_client.go:355-359）。
- 选路分支：region 模式 → `dialRegion`；返回后 `idealNodeInRegion := err == nil && reg.Nodes[0] == node`（derphttp_client.go:436-440）。

### 4.2 dialRegion：按序、跳 STUNOnly、firstErr（derphttp_client.go:636-657）

```go
// dialRegion returns a TCP connection to the provided region, trying
// each node in order (with dialNode) until one connects or ctx is done.
func (c *Client) dialRegion(...) {
    if len(reg.Nodes) == 0 { return …, fmt.Errorf("no nodes for %s", …) }
    var firstErr error
    for _, n := range reg.Nodes {          // ← 数组序，无洗牌
        if n.STUNOnly {                    // ← STUN-only 节点不能承载 DERP
            if firstErr == nil { firstErr = fmt.Errorf("no non-STUNOnly nodes for %s", …) }
            continue
        }
        c, err := c.dialNode(ctx, n)
        if err == nil { return c, n, nil } // ← 首个可连即用
        if firstErr == nil { firstErr = err }
    }
    return nil, nil, firstErr              // ← 全败返回“第一个”错误
}
```

`DialRegionTLS`（netcheck HTTPS 测速入口）复用同函数，文档注释原文："DERP nodes for a region are tried in sequence according to their order in the DERP map. TLS is initiated on the first node where a socket is established."（derphttp_client.go:680-685）。**同款实现至少存在于 v1.36.0**（对照实拉：v1.36.0 `derp/derphttp/derphttp_client.go:503-509` 同为按序 `for _, n := range reg.Nodes` + STUNOnly 跳过）——按序回退语义长期稳定，不是新近行为。

### 4.3 dialNode：v4/v6 竞速、1500ms、端口（derphttp_client.go:729-837）

- 单节点预算 `dialNodeTimeout = 1500 * time.Millisecond`（derphttp_client.go:729, 760）。
- 目标地址：每个地址族一个 goroutine，`dst := cmp.Or(dstPrimary, n.HostName)`——**显式 `n.IPv4`/`n.IPv6` 字段优先，否则 HostName 走 DNS**（derphttp_client.go:766-767）；族校验：字段非空但解析不出对应族（如 `"none"`）则该族不发车（`shouldDialProto`，derphttp_client.go:721-727；族错配防呆 771-776）；两族全禁 → `errors.New("both IPv4 and IPv6 are explicitly disabled for node")`（derphttp_client.go:815-817）。
- 端口：默认 `"443"`（调试 `TS_DEBUG_USE_DERP_HTTP` 下 `"3340"`），`n.DERPPort != 0` 覆盖（derphttp_client.go:792-798）。注意 HTTP URL 形态 `urlString` 只在 `DERPPort` **既非 0 也非默认值**时才显式带端口（derphttp_client.go:288-293）。
- IPv6 偏好：`preferIPv6()` 时 IPv4 竞速者先睡 200ms（derphttp_client.go:780-791）；偏好来自 magicsock 注入的 selector = **上次 netcheck report 的 `IPv6` 布尔**（ms-derp.go:1054-1068）。
- 结果收集：unbuffered channel + `nwait` 计数，首胜即返；全败返回 firstErr；ctx 结束（含 1500ms 超时）立即失败（derphttp_client.go:759-836）。
- HTTP 代理场景另有 `dialNodeUsingProxy`（CONNECT 隧道，端口选择与 dialNode 保持同步——derphttp_client.go:846-921），本仓一期可不做（D4 核心零网络，代理属 app 侧拨号策略）。

### 4.4 连到非理想节点时的信令（derphttp_client.go:439, 513-524）

- `idealNodeInRegion == false`（连到了 `Nodes[0]` 以外的节点）→ 请求头 `Ideal-Node: <reg.Nodes[0].Name>`，注释原文 "This is purely informative for now (2024-07-06) for stats"（derphttp_client.go:513-524）；服务端将其记为 `isNotIdealConn` 统计（归档 derpserver.go:69-71, 1173）。
- **主动迁移回理想节点是 TODO**（"start a time.AfterFunc … dialNode(reg.Nodes[0])"，tracking issue #12724，derphttp_client.go:516-523）——**未实现**。实现者不要据此发明「客户端定期迁回首节点」的行为。

### 4.5 TLS 层与字节级细节（derphttp_client.go:271-294, 473-534, 659-678）

- SNI：region 模式 = `node.HostName`（derphttp_client.go:271-277）。
- 证书校验：`node.CertName != ""` 时设置期望证书；**`sha256-raw:` 前缀** → 按 SHA256 钉扎，否则按名字（derphttp_client.go:669-675；语义来源 derpmap.go:204-214）。`InsecureForTests` 仅测试用（derphttp_client.go:664-667）。
- metacert 快速启动：TLS 1.3 下证书 CN = `"derpkey" + 服务器公钥 hex`、serial = DERP 协议版本（≤255）时，客户端可解析出服务器公钥，随即带 `Derp-Fast-Start: 1` 头抑制服务端 HTTP 响应（derphttp_client.go:495-499, 526-534, 1184-1196；`MetaCertCommonNamePrefix="derpkey"`，derpconst.go:7-11；`FastStartHeader="Derp-Fast-Start"`，derp.go:166-170）。
- HTTP 升级请求（字节级要点）：`GET https://<host>[:<DERPPort>]/derp HTTP/1.1` + `Upgrade: DERP` + `Connection: Upgrade`（derphttp_client.go:507-512）；其上即本仓已对齐的 DERP 帧层（帧头 1B type + **u32 大端**长度，derp.go:36 `FrameHeaderLen = 1 + 4`，再证 architecture.md §10.2 AU2；首帧 ServerKey 载荷 = Magic `"DERP🔑"` 8B `0x44 45 52 50 f0 9f 94 91` + 32B 公钥，derp.go:32）。

## 5. 降级与重连：失败后怎么走（ms-derp.go + derphttp_client.go）

按故障场景归纳（全部有行号锚点）：

1. **单节点拨号失败** → `dialRegion` 原地继续下一个节点（derphttp_client.go:641-655）；单节点最多耗 1500ms，region 全列表受 10s 总预算约束（≥7 节点的 region 尾部节点可能轮不到——实现测试要按此语义设断言）。
2. **region 全节点失败** → `connect` 返回 firstErr（第一个节点的错误）；`Send/Recv` 把错误抛给调用方，但 `closeForReconnect` 已把连接置空，**下一次**调用自动重新走 §4.2（derphttp_client.go:52-56, 923-932, 1103-1131, 1169-1180）。
3. **建连后的读错误**（含服务器断连）→ `runDerpReader`：标记 region 断连、遗忘该 region 全部 peer 路由、`ReSTUN("derp-recv-error")`（网络变了可能连 home 都该换）、`backoff`（上限 5s，ms-derp.go:558, 562-598）后**循环回到 `RecvDetail` → 同一 region 重连**。注意：**读错误不会立刻换 home/region**——换 home 只由 netcheck 周期驱动（§3.3）。
4. **UDP 被封 / netcheck 无数据** → `pickDERPFallback` 随机选 region 兜底（§3.3）；metric `metricDERPHomeFallback` 计数（ms-derp.go:146）。
5. **netcheck 降级测速** → STUN 全挂时对全部候选 region 走 HTTPS `/derp/latency-check` + ICMP `Nodes[0]`（§3.2）。
6. **DERPMap 更新** → `setDERPMap`：逐 region `DeepEqual` 比较，**home region 定义变化则 `c.myDerp = 0` 并关闭该连接（"derp-region-redefined"）**，随后触发 ReSTUN 重新选 home（ms-derp.go:814-877）。
7. **接口重绑定** → `maybeCloseDERPsOnRebind`：本地地址不在白名单或 Ping(3s) 失败的连接关闭/重连（ms-derp.go:908-935）。
8. **空闲回收** → 非 home 连接 60s 无写即关，15s 扫描周期（ms-derp.go:990-1034, 1070-1078）；home 关闭则立即重连（`closeOrReconnectDERPLocked`，ms-derp.go:944-949）。
9. **服务端健康信令** → `Health` 帧 → `health.SetDERPRegionHealth(regionID, problem)`（ms-derp.go:649-651）；`PeerGone` 帧删除对应 peer 路由（ms-derp.go:652-666）。
10. **服务端 keepalive 节奏** → 服务端每 `derp.KeepAlive + rand.N(5s)`（60s ± <5s 抖动）发一帧（归档 derpserver.go:2634-2636）；客户端侧「2×60s 无帧才算失联」（netcheck.go:1393-1401 注释）。本仓 `packages/derp/src/client.ts` 对 KeepAlive 帧静默消费，**超时判定属于上层/netcheck**，不要塞进帧层。

## 8. 实现陷阱清单（给 S-执行）

1. **不要按任务标题字面实现「region 内随机洗牌」**：上游语义是按序回退（§4.2）；「随机」只存在于 region 级兜底（§3.3）。若确需偏离上游（比如想打散负载），那是接口语义变更，须按 TASK.md 红线留痕并在 AU 清单标注偏离，而不是冒充上游行为。
2. **STUNOnly 缺字段**：不补 `stunOnly` 就无法表达「同 region 里混部纯 STUN 节点」——dialRegion 第一个该跳的判断就错（derphttp_client.go:641-647）。
3. **`firstErr` 语义**：全失败时返回**第一个**错误（不是最后一个）；测试断言别写反。
4. **预算叠加**：10s 是**整场**（含 TLS+升级），1500ms 是**单节点**；大 region 尾部节点可能永远轮不到——「按序全试」不等于「每节点都试到」。
5. **`none` 与空串不同**：`IPv4:""` = 走 DNS（v4）；`IPv4:"none"` = v4 禁用；既非合法 v4 又非 none 的字符串同样按禁用处理（shouldDialProto 的 `pred` 判定，derphttp_client.go:721-727）。
6. **理想节点迁移是 TODO**：`Ideal-Node` 头只是统计（derphttp_client.go:514）；不要实现「定期迁回 Nodes[0]」并声称对齐上游。
7. **读错误 ≠ 换 home**：连接断了是「同 region 重连 + ReSTUN」，换 home 只等 netcheck 新报告（§5.3）；同理 netmap 缓存的 homeDERP 在无控制面连接且有 home 时保持不变（ms-derp.go:186-195）。
8. **DERPMap 更新的 home 失效**：home region **定义**（整对象 DeepEqual）变化时 myDerp 必须清零重选（ms-derp.go:853-869）——只比较 regionId 不够。
9. **随机必须经 Rng**（P4/G0-5）：即便实现 region 级兜底随机，也用 `@ohos-tailscale/common` 的 `Rng`；上游 `rands.IntN` 是「seed 播种 PCG-DXSM + Lemire 归约」（cheap.go:28-34），测试可用 ArrayRng/固定 seed 复现；**不要**移植 `uintptr(unsafe.Pointer(c))` 的取种方式（JS 无对应物），取种方式交给注入方。
10. **CertName 的 `sha256-raw:` 形态**：app 侧 TLS 校验（CertName 优先、HostName 回退之外）还要支持证书 SHA256 比对形态（derpmap.go:209-213；derphttp_client.go:670-671）——自建 DERP 用自签证书时是唯一可用形态。
11. **home 迟滞勿省**：`homeRegion` 若做成每帧裸最小值，bufferbloat 下会抖动换 home——上游为此加了两层迟滞 + 8s 帧/120s keepalive 信号（§3.1）；本仓一期至少实现「并列/近差时保留当前 home」。
12. **headscale 下发的节点序不可证**：`Nodes`「按当前客户端定制优先序」是 Tailscale SaaS 控制面的行为（derpmap.go:171-172 注释）；headscale 如何排序本仓未归档其源码，**不可证**。客户端按「收到的数组序=优先序」处理即可，不要依赖「headscale 会帮我随机」。
13. **帧层勿动**：本笔记不改变已冻结的帧协议事实（u32BE 帧头/Magic/ClientInfo，AU2 已核对）；§6 常量表仅新增上层策略常量。
14. **本 ask 写入限制**：§0.2 所列实拉原文尚未归档进 `docs/upstream/`——执行会话开工前应先补归档（TASK.md:36 B-1 要求原文归档），行号以本笔记为准复核。
